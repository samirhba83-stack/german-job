# 12. Accessibility During Interaction

## Real, implemented, checkable in the code

**Loading states**: `Skeleton`/`SkeletonRegion` set `aria-busy`/`aria-live="polite"` ([04](04-interaction-feedback-system.md)); `Button`'s `loading` prop sets `aria-busy` on the button itself.

**Focus management**: `MobileNavDrawer` traps interaction to its own content while open (backdrop click closes, `role="dialog" aria-modal="true"`) and locks `document.body.style.overflow` while open; `DropdownMenu` closes and returns interaction to the trigger on outside-click or `Escape`. `globals.css`'s `:focus-visible` rule applies a real 2px accent ring, offset, to every focusable element platform-wide — not per-component, so nothing can silently omit it (matches [M21 §9](../design-system/09-accessibility.md)'s "never suppressed for mouse users" rule — the ring is not gated on any input-modality detection at all, styled identically regardless of pointer vs. keyboard).

**Keyboard navigation**: every interactive element built this milestone is a real `<button>`, `<a>`, or `<input>` — never a `<div>` with an `onClick` and no keyboard path (checked directly against every file in `components/ui/` and `components/shell/`). `DropdownMenuTrigger` explicitly handles `Enter`/`Space`. `Tooltip` triggers on `onFocus` as well as `onMouseEnter`.

**Two real defects found and fixed by Milestone 22.2's self-review**: M22's `DropdownMenuTrigger` wrapped an already-interactive child (a `<button>`) in a second interactive `<span role="button" tabIndex={0}>` — invalid, double-focusable, and confusing for assistive technology. It's now an "asChild" pattern (`Children.only` + `cloneElement`) that attaches the open/close handlers directly to the real trigger element instead of wrapping it. Separately, `DropdownMenuItem` nested a real `<Link>` (which renders `<a>`) inside a `<button role="menuitem">` — invalid, interactive-content-inside-interactive-content HTML, present in the shipped Profile Menu's Profile/Settings items. It now accepts an `href` prop and renders a single `<Link role="menuitem">` directly instead of nesting two interactive elements.

**Real WAI-ARIA APG menu navigation (Milestone 22.2)**: `DropdownMenuContent` declared `role="menu"`/`"menuitem"` since M22 but had no actual arrow-key navigation behind that semantics — a real gap between claimed and actual behavior. It now implements the [ARIA Authoring Practices Guide menu pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menu/): `ArrowDown`/`ArrowUp` move focus between `[role="menuitem"]` elements with wraparound, `Home`/`End` jump to the first/last item, and opening the menu (including via the trigger's `ArrowDown`) auto-focuses the first item.

**Focus restoration on close, and a real HTML-validity fix (Milestone 22.3)**: the audit found `DropdownMenuContent`'s own code comment claimed Escape "returns focus to the trigger" when it didn't — closing the menu unmounted the focused menuitem with nothing to catch focus, silently dropping a keyboard user's position to `<body>`. Fixed for both Escape and a non-navigating item selection (log out, retry, a theme change); deliberately not applied to `href` items, where a real navigation should take focus instead ([13, ADR-011](13-decision-records.md)). Separately, `DropdownMenu`'s root wrapped a block-level `role="menu"` `<div>` inside a `<span>` — invalid HTML content model, present at every call site — fixed by changing the wrapper to a `<div>` with identical layout behavior ([13, ADR-010](13-decision-records.md)). A third, same-class defect was found and fixed outside `DropdownMenu` entirely: the Dashboard root page nested a `Card interactive` (which sets its own `tabIndex={0}`) inside a real `<Link>`, the identical double-focusable pattern in a different component ([13, ADR-012](13-decision-records.md)).

**Announcements**: `Toaster` renders each toast with `role="status" aria-live="polite"` ([04](04-interaction-feedback-system.md)); the Background Activity Center's list has `aria-live="polite"` so a completed/failed transition is announced without the user needing to reopen the panel.

**Reduced motion**: `globals.css`'s global `@media (prefers-reduced-motion: reduce)` rule forces every animation/transition duration to near-zero platform-wide — implemented once, centrally, rather than requiring every component to check the media query itself. This is a real, verified CSS rule in the shipped `globals.css`, not a documented intention.

**Screen readers**: every icon-only button in the shell (`Menu`, `Bell`, `X`, the Background Activity trigger) has a real `aria-label` naming the action; every purely decorative icon paired with visible text uses `aria-hidden="true"` (checked across `global-header.tsx`, `notification-area.tsx`, `background-activity-center.tsx`, `profile-menu.tsx`).

**High contrast (Milestone 22.2)**: `globals.css` now has a real `@media (prefers-contrast: more)` layer — a standard media feature (macOS "Increase contrast," Windows "High contrast"), not a bespoke app setting. It strengthens the existing token values (`--color-border-default`, `--color-text-secondary` move to a darker/lighter neutral step depending on theme; the focus ring widens from `ring-2` to `ring-[3px]`) rather than introducing a separate high-contrast palette, and is layered to apply correctly under light, dark, and system-preference theme combinations, mirroring the existing dark-mode CSS structure.

**Large screens**: covered structurally by [11-responsive-interaction.md](11-responsive-interaction.md)'s `3xl` breakpoint handling (content capped at `max-w-content`, extra side padding) — not a separate accessibility mechanism, since large-screen usability here is a layout concern, not an assistive-technology one.

## What this milestone did not verify

No automated accessibility audit (axe, Lighthouse) was run against the live shell — the same gap [M21's own accessibility document](../design-system/09-accessibility.md) already flagged as outstanding (calculated contrast ratios, not tool-verified). This milestone's contribution is that the *implementation* now exists to audit; the audit itself remains real, outstanding work, named in [14-risks-and-future-expansion.md](14-risks-and-future-expansion.md).
