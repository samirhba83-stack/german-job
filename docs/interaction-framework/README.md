# Milestone 22 / 22.2 / 22.3 — Intelligent Interaction Framework & Application Shell

**Date**: 2026-07-25 (M22), extended 2026-07-25 (M22.2), audited 2026-07-25 (M22.3)
**Scope**: the first *implementation* milestone. Real, working code in `apps/web` — a production build was run, lint passes clean, and the shell was verified against the live backend (real register/login calls, real bugs found and fixed). No business logic, no invented APIs, no dashboard/Mission Control/Campaign/Company Workspace pages — those are explicitly reserved for the next milestone.

**Milestone 22.2** is a self-review-driven hardening pass over the same shell: it found and fixed real defects in the M22 implementation (nested interactive elements, missing keyboard navigation, an unreachable mobile search entry, missing error/loading boundaries, unnecessary re-renders, a Background Activity Center with zero real callers) and built the shell elements M22.2 requested that M22 didn't yet have (Workspace Switcher, Theme Switcher, Context Header, a real Accordion, a real Trust Feedback Card, high-contrast support). See [15-milestone-22-2-self-review.md](15-milestone-22-2-self-review.md) for the full brutally-objective review.

**Milestone 22.3** is a complete production-readiness audit performed before Milestone 23 begins — every file in `apps/web/src` was re-read, not just the files each prior milestone already knew it had touched. It found and fixed a production-blocking defect the two prior milestones both missed: nine real navigation targets (Sidebar items, Quick Actions, Profile Menu links) pointed at routes with no page at all, one of which silently rendered the *wrong* page rather than erroring. It also found a repeat instance of a defect class M22.2 believed it had already fixed everywhere, a route-level authorization gap, and several smaller consistency issues. See [16-milestone-22-3-production-audit.md](16-milestone-22-3-production-audit.md) for the full report and its READY/NOT READY verdict. This document set is updated in place — the docs below describe the current, combined M22+M22.2+M22.3 state of the code, not three separate snapshots.

## Executive Summary

This milestone built the permanent Application Shell and Interaction Framework as real code, not a specification — and in doing so, found and fixed two genuine integration bugs that no amount of further architectural documentation would have caught. Testing the frontend against the actual running backend revealed that the global `TransformInterceptor` wraps every successful response in `{ data: T }` (resolving [M20's own open question, OQ-9](../frontend-architecture/13-risks-and-open-questions.md), which had been sitting unverified since that milestone), and that NestJS's built-in exceptions nest their error message inside `{ message: { message, error, statusCode } }` rather than the flat shape M20's documentation assumed. Both were fixed in `lib/api-client.ts` before this milestone's own verification was considered complete — see [13, ADR-003 and ADR-004](13-decision-records.md) for the full account, including the real request/response bodies that proved each finding.

The shell itself (`components/shell/`) implements every element the milestone requested — Global Header, Primary Sidebar, Context Navigation, Breadcrumbs, Workspace Area, Notification Area, Profile Menu, Global Search Entry, Quick Actions, Responsive Navigation — wired to real authentication (`lib/stores/auth-store.ts`, real JWT decoding, real token refresh) and real navigation data (`lib/navigation.ts`, permission-filtered by the actual authenticated user's role). The Interaction Framework's centerpiece is `lib/hooks/use-tracked-mutation.ts`: a single hook that gives every mutation in the product automatic Background Activity Center tracking and toast acknowledgment, so the milestone's "every request has progress, every completed action is acknowledged, every failure is explained" principle is a structural property of the codebase rather than a convention each feature has to remember to follow.

The milestone's own repeated constraint — "never simulate progress," "no mock workflows," stated three separate times in its own text — was taken as seriously as every prior milestone's honesty discipline. Several of the milestone's own example execution stages (Analyzing Companies, Generating CV Package, Checking Policies) map to real domain concepts with zero HTTP exposure today ([execution-tracking](../frontend-architecture/01-information-architecture.md), `recommendations`, `application-assembly`, `business-policy-enforcement` — all confirmed dormant across every prior milestone). Rather than fabricate a plausible-looking progress sequence for these, [`ExecutionStageList`](03-execution-feedback.md) was built fully generic and data-source-agnostic, wired only to the one execution sequence that *is* real and live today — the Application lifecycle's real, timestamped transitions.

## Milestone 22.2: the self-review pass

M22.2 explicitly required treating M22 as *not complete* and re-reading its own code "as a Principal Frontend Engineer at Stripe," rather than defending what already existed. That review found real defects, not stylistic nitpicks: `DropdownMenuTrigger` wrapped an already-interactive `<button>` in a second interactive `<span role="button">`; `DropdownMenuItem` nested a real `<Link>` (renders `<a>`) inside a `<button role="menuitem">` — invalid, interactive-inside-interactive HTML present in the shipped Profile Menu; `role="menu"`/`role="menuitem"` were declared with no actual arrow-key/Home/End navigation behind them; the Global Search Entry was `hidden md:flex` with no mobile alternative at all; no `error.tsx`/`loading.tsx` existed anywhere, so an uncaught render error blanked the whole app; `AppShell` and `use-auth.ts` both destructured the entire Zustand auth store, re-rendering the whole shell on every silent token refresh; and — the largest finding — `useTrackedMutation` and the Background Activity Center had been built in M22 but never actually wired to a real call site, so the milestone's own centerpiece feature had zero real users until this pass rewired `use-auth.ts` to use it. Each was fixed with a real code change, not documented and left. Full account: [15-milestone-22-2-self-review.md](15-milestone-22-2-self-review.md).

M22.2 also built the shell elements the milestone requested that M22 hadn't gotten to: a real Theme Switcher (Light/Dark/System) backed by a pre-hydration boot script so there's no flash of the wrong theme; a Workspace Switcher that honestly shows the single real workspace a user has today rather than a fabricated multi-workspace picker; a generic Context Header primitive; a real Accordion and a real `TrustFeedbackCard`; a `prefers-contrast: more` layer over the existing design tokens; and expanded, real data models for Mission Status (adds Recovering/Cancelled, wires `CampaignHealth.healthScore` as confidence) and the Background Activity Center (duration, retry, related-context fields).

## Milestone 22.3: the production-readiness audit

M22.3 was explicit that this milestone is not feature work — it's the final engineering audit before Milestone 23 builds on top of this shell, performed by re-reading every file, not re-reading M22.2's own list of what it already knew it had checked. That distinction mattered: it surfaced a production-blocking defect neither M22 nor M22.2 had found — nine real navigation targets (`/campaigns`, `/companies`, `/settings`, `/profile`, `/mission-control`, `/admin`, and three Quick Actions creation routes) had no page at all, and one (`/jobs/new`) silently rendered the *wrong* page rather than erroring, due to Next.js's static-before-dynamic route precedence. It also found a repeat instance of a defect class M22.2 believed it had eliminated (a `Card` nested inside a `<Link>`, reproducing the exact "two focusable elements for one action" bug DropdownMenu had already been fixed for, just in a different component M22.2 never checked), a real gap between a code comment's claim and the code's actual behavior (Escape claimed to restore focus to a dropdown's trigger; it didn't), and a route-level authorization gap. All were fixed with real code changes. Full account, including the complete audit across architecture/components/state/performance/accessibility/security/navigation/maintainability/trust, and the evidence-backed verdict: [16-milestone-22-3-production-audit.md](16-milestone-22-3-production-audit.md).

## Readiness assessment (full version in §16)

**READY FOR MILESTONE 23.** Every piece of shell/interaction infrastructure Dashboard, Campaign Workspace, and Company Workspace need (auth, navigation, mutation tracking, toasts, status badges, loading states, and now a verified-correct set of navigation targets with no dead links anywhere in the product) exists, builds cleanly, and has been proven against the live backend. Mission Control remains correctly gated on the same backend readiness gap ([M20](../frontend-architecture/README.md), [M20.5](../product-experience/README.md), [M20.6](../career-intelligence/README.md) all independently concluded this) — nothing in this milestone changes that conclusion. The audit's own named outstanding items (no automated accessibility tooling, no component test suite, an ambiguous `NavItem.status` field) do not block Milestone 23 and are listed as real, future work in [§16's Future Recommendations](16-milestone-22-3-production-audit.md#future-recommendations).
