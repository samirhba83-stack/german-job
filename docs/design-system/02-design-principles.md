# 2. Design Principles

Twelve permanent rules — the visual-layer counterpart to [Product Experience's 18 Experience Principles](../product-experience/15-experience-principles.md). Where those govern tone and behavior, these govern pixels. Every component in [§7](07-component-library.md) and every visual decision in this document set should be checkable against this list.

1. **Consistency over decoration.** The same spacing rhythm, the same radius, the same shadow depth, applied identically everywhere a given pattern appears — a component never gets a bespoke visual treatment "because this screen is special."
2. **Function before aesthetics.** A visual choice that makes a component prettier but harder to scan or slower to parse loses, every time, without exception.
3. **Information hierarchy first.** Size, weight, and spacing establish what matters most on a screen before color ever does — color is a reinforcing signal, never the primary one (directly enables §9's color-blind-safe requirement, since hierarchy that depends only on color fails immediately for anyone who can't perceive it).
4. **Minimal cognitive effort.** Fewer simultaneous visual signals, not more — a status conveyed by badge shape/label/color together is still *one* signal to parse, not three competing ones.
5. **Predictable interactions.** An element that looks clickable is clickable, everywhere, with the same affordance (cursor, hover state, focus ring) it has anywhere else in the product — no exceptions for "just this one card."
6. **Transparency through design.** Loading, empty, and error states are visually distinct from each other and from populated content by construction (extends [Product Experience's Loading Experience](../product-experience/12-loading-experience.md)/[Empty State Philosophy](../product-experience/10-empty-state-philosophy.md) into their visual treatment) — a user should never have to read carefully to tell which state they're looking at.
7. **Accessibility by default, not as a retrofit.** Every token, every component contrast pair, every focus state is designed to pass WCAG 2.1 AA from first definition (§9) — accessibility is never a pass applied after visual design is "done."
8. **Explainability through visual hierarchy.** An AI-originated claim (a recommendation, a confidence score, a pattern) is never visually indistinguishable from a plain system fact — §12 defines the specific, consistent visual grammar that keeps evidence and reasoning legible at a glance, every time.
9. **One accent color, spent deliberately.** The brand accent (§3) marks primary actions and only primary actions — every other use of color is semantic (status) or structural (neutral surface/text/border), so the one moment the accent appears, it means something.
10. **Density with room to breathe.** This is a data-dense operational tool (tables, timelines, execution history), not a sparse marketing site — but density is achieved through disciplined spacing and type-scale choices (§3, §4), never by cramming content with no whitespace at all.
11. **Motion communicates, never decorates.** Reused directly from [M20 §11](../frontend-architecture/11-design-system-foundation.md)'s animation principles and given its full specification in [§8](08-motion-system.md) — if a proposed animation doesn't communicate a state change, it doesn't ship.
12. **The system is the source of truth, not the screen.** No screen invents a new color, spacing value, radius, or type size that isn't already a token. A missing token is a reason to propose a new token (via a Design Decision Record, §13), never a reason to reach for a raw value.
