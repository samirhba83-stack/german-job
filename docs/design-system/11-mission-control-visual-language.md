# 11. Mission Control Visual Language

## Grounding note

Every element below visualizes a real, named data structure from prior milestones — [M20's Mission Control screens](../frontend-architecture/03-screen-inventory.md) (🟡 dormant, no controller), [Career Intelligence's](../career-intelligence/README.md) reserved `CampaignIntelligence`/`CompanyMemoryEntry` fields, and [Product Experience's Trust Architecture](../product-experience/03-trust-architecture.md). This section defines what those would look like *when connected* — the visual language ships now so implementation has zero redesign work the moment the backend catches up, exactly the pattern [M20's ADR-008](../frontend-architecture/12-architecture-decision-records.md) and [Career Intelligence's ADR-007](../career-intelligence/12-architecture-decision-records.md) already established for "honest not-yet-connected states."

## Mission Timeline
**Visualizes**: the Campaign Timeline projection (real, tested, 🟡 dormant). **Treatment**: the [§7 Timeline component](07-component-library.md), with node color = the event's semantic tone and node icon = the event type ([§6](06-iconography.md)) — never a generic dot. Time-scale is honest: real gaps between events render as real visual gaps (proportional spacing), never compressed to look busier than the actual event frequency — a direct visual expression of [Career Intelligence's "no simulated learning"](../career-intelligence/01-career-intelligence-principles.md) principle applied to time itself.

## Germany Campaign Map
**Visualizes**: the Germany Coverage projection — real, verified company-location data only ([M19's "never estimate location" rule](../M19-VALIDATION-REPORT.md), already carried into [§8's motion rules](08-motion-system.md)). **Treatment**: a choropleth by federal state, fill intensity = `indigo-600` at increasing opacity steps (never a rainbow gradient — a single-hue intensity scale keeps "more activity" legible without introducing a second, competing color language). Regions with zero verified data render at `neutral-100`, **not** a light tint of the accent color that could be mistaken for "a little activity" — an important, deliberate distinction between "true zero" and "small non-zero," matching [Career Intelligence's minimum-evidence honesty](../career-intelligence/04-pattern-detection-blueprint.md).

## Execution Cards
**Visualizes**: one execution attempt's real audit trail (`ExecutionEvent`, 🟡). **Treatment**: Card spec ([§7](07-component-library.md)) + Status Badge for the outcome + a compact Timeline showing the attempt's own step sequence (Recommendation → Decision → Planning → Orchestration → Runtime → Worker → Provider → Delivery) — every step shown, including steps that failed, never trimmed to only show the happy path (directly enforces [Product Experience's "show evidence before conclusions"](../product-experience/03-trust-architecture.md)).

## Confidence Indicators
**Visualizes**: `DecisionReport.confidenceScore` / `Recommendation.expectedImpactScore` / [Career Intelligence's confidence bands](../career-intelligence/06-learning-confidence-framework.md). **Treatment**: a horizontal segmented bar (4 segments matching Low/Moderate/High/Very High) with the achieved band filled in the matching intensity of `indigo-600` and the real percentage/score printed alongside in Numbers typography ([§4](04-typography-system.md)) — never just a color with no number, per [§4 AI Visual Language](12-ai-visual-language.md)'s core rule. Full specification in [§12](12-ai-visual-language.md), since this same indicator is this system's primary AI-communication device, not Mission-Control-specific.

## Recommendation Cards
**Visualizes**: a `Recommendation`, per [Product Experience's Decision Explanation Framework](../product-experience/07-decision-explanation-framework.md) template. **Treatment**: Card spec, with a fixed internal layout — headline (`text-heading-md`) → Confidence Indicator (above) → evidence summary (`text-body-sm`) → an Accordion ([§7](07-component-library.md)) collapsed by default containing the full "what else we considered" detail. The fixed layout matters: every Recommendation Card looks identical in structure regardless of content, so a user learns to scan it once and can then scan any future one at the same speed — a direct visual expression of [Design Principle 5, predictable interactions](02-design-principles.md).

## Career Health Widgets
**Visualizes**: [Career Intelligence's nine Career Health dimensions](../career-intelligence/07-career-health-score.md) — never one composite number, per that document's own ADR-002. **Treatment**: nine individual Statistic/Progress Cards ([§7](07-component-library.md)) in a grid, each showing its own Confidence Indicator, never a single dashboard gauge implying one aggregate score. A dimension with insufficient evidence renders as a **visually distinct "not yet available" card state**: `neutral-100` fill instead of the populated card's `surface.default`, an outlined (not filled) icon, and the exact copy pattern [Career Intelligence's ADR-007](../career-intelligence/12-architecture-decision-records.md) specifies — never a `0` or blank number standing in for "unknown."

## Decision Reports
**Visualizes**: a full `DecisionReport` — the richest single explanation surface in the product. **Treatment**: composes a Recommendation Card (above) for the `finalRecommendation`, followed by an explicit "Alternatives considered" section listing every `ConflictGroup` candidate at reduced visual weight (`opacity-subtle`, [§3](03-design-tokens.md)) with its own brief rejection reason — the losing alternatives are never fully hidden, only visually de-emphasized relative to the winner, so a user can always audit the full decision without it competing for primary attention.

## The one rule that governs all seven

**Trust and operational transparency are communicated through completeness and consistency, not through visual intensity.** None of the elements above uses saturated color, motion, or scale to seem more important or more certain than its underlying data supports — every one of them is calm, structured, and evidence-first, exactly matching [§1's](01-design-philosophy.md) "Trustworthy" and "Calm" traits and [Product Experience's Trust Architecture](../product-experience/03-trust-architecture.md) applied to pixels.
